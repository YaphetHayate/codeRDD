# Code Compass — 项目代码理解加速器 & RDD Skill 导航基础设施

## 它解决什么问题

面对陌生项目时，人类开发者和 AI Agent 都需要花费大量时间阅读代码才能回答：
- 项目有哪些模块，各自负责什么？
- 代码的入口在哪，业务流程怎么流转？
- 改一行代码会影响哪些地方？
- 某个功能涉及哪些文件，需要修改哪里？

Code Compass 通过**预先构建结构化索引 + 按需查询**，让这些信息**一次构建、按需获取**，避免反复阅读源码。

## 核心能力概览

| 指令 | 功能 | 典型场景 |
|------|------|----------|
| `/understand` | 建立项目全局上下文 | CTO Phase 1、接手新项目 |
| `/navigate` | 定位目标代码位置 | DEV 任务分析、修改功能 |
| `/trace` | 追踪代码执行流向 | 理解业务流程、定位 Bug |
| `/impact` | 评估代码改动影响 | CTO 方案评估、DEV 改动分析 |
| `/map` | 构建/更新代码索引 | 首次运行、代码变更后 |
| `/readme` | 生成项目文档 | 项目初始化、文档缺失 |

## 指令详解

### `/understand` — 建立项目全局上下文

快速理解项目整体架构，生成结构化摘要供其他 skill 使用。

**执行流程**：

1. **读取 `.code-compass/overview.md`**（如果存在）
2. **如果索引不存在或过期**，先执行 `/map` 构建索引
3. **读取索引核心数据**：
   - `manifest.json` — 文件列表、统计信息
   - `overview.md` — 目录结构概览
   - `entries.json` — 入口点汇总
4. **生成结构化上下文摘要**，格式：

```markdown
## 项目上下文摘要

**项目概览**：
- 项目类型：[类型]
- 技术栈：[语言/框架列表]
- 规模：[文件数、方法数、入口点数]

**目录结构**：
- [模块A] → [职责描述]
- [模块B] → [职责描述]
- ...

**核心入口点**：
1. [入口1] — [业务描述]
2. [入口2] — [业务描述]
...

**关键模块依赖关系**：
[简要描述模块间的上下游关系]
```

**自动触发规则**：
- CTO 模式进入 Phase 1 "理解项目现状" 时，必须先执行此指令
- DEV 模式进入任务分析阶段时，必须先执行此指令
- 其他 skill 需要快速理解项目时主动调用

> 详细实现见 `references/query/query-commands.md`。

### `/navigate` — 定位目标代码位置

根据关键词或功能描述，精确定位相关代码文件。

**执行方式**：

```
/navigate <关键词或功能描述>
```

**示例**：
```
/navigate 用户登录
/navigate 创建订单
/navigate employee
```

**执行流程**：

1. **读取 `entries.json`**，按关键词匹配入口点
2. **如果入口点匹配不足**，搜索 `methods/*.json` 中的方法名和签名
3. **如果仍不足**，直接搜索源码文件
4. **输出定位结果**：

```markdown
## 定位结果：[关键词]

**匹配入口点**：
- [入口路径] → [文件:行号] ([置信度])

**相关方法**：
- [方法路径] → [文件:行号] (定义处)
- [方法路径] → [被调用于] (调用处)

**涉及文件清单**：
1. [文件A] — [匹配原因]
2. [文件B] — [匹配原因]
```

> 详细实现见 `references/query/query-commands.md`。

### `/trace` — 追踪代码执行流向

从入口点出发，追踪代码的执行链路。

**执行方式**：

```
/trace <入口点标识>
```

**示例**：
```
/trace POST /api/users/login
/trace create_order
```

**执行流程**：

1. **定位入口点**，从 `entries.json` 获取入口信息
2. **读取入口的调用关系**，从 `calls/*.json` 获取直接调用
3. **递归展开调用链**，按深度逐步展示
4. **输出追踪结果**：

```markdown
## 执行流追踪：[入口标识]

```
[入口函数]
  └─→ [函数A] (文件A:行号)
        └─→ [函数B] (文件B:行号)
              └─→ ...
```

**调用链详情**：
- [层级1] [函数签名] — [简要说明]
- [层级2] [函数签名] — [简要说明]
...

**涉及的模块**：[模块列表]
```

> 详细实现见 `references/query/query-commands.md`。

### `/impact` — 评估代码改动影响

分析修改某个文件/函数会影响的范围。

**执行方式**：

```
/impact <文件路径或函数名>
```

**示例**：
```
/impact services/user_service.py
/impact create_order
```

**执行流程**：

1. **如果是文件**，读取 `calls/{file}.json` 获取 `called_by` 信息
2. **如果是函数**，先定位函数所在文件，再查询影响
3. **递归向上追踪**所有上游调用方
4. **输出影响评估**：

```markdown
## 影响评估：[目标]

**直接影响**（直接调用此代码的位置）：
- [调用方A] → [文件:行号]
- [调用方B] → [文件:行号]
...

**间接影响**（调用方的调用方）：
- [间接调用方A] → [文件:行号]
...

**涉及入口点**（此代码被哪些业务入口触发）：
- [入口1]
- [入口2]
...

**风险提示**：
- [潜在风险点1]
- [潜在风险点2]
...
```

### `/map` — 构建/更新代码索引

构建项目的结构化代码索引系统。

**执行方式**：
- `/map` — 构建或增量更新索引
- `/map --refresh` — 强制刷新所有入口的业务描述

**详细流程**见 `references/map/map.md`。

### `/readme` — 生成 README 文档

自动生成项目 README.md。

**执行方式**：
- `/readme` — 生成 README.md

**详细流程**见 `references/readme-generator/readme-generator.md`。

## 索引存储结构

索引数据存储在项目根目录的 `.code-compass/` 下：

```
.code-compass/
├── manifest.json      # 全局索引（文件列表、状态统计）
├── overview.md        # 目录结构概览（人类可读）
├── methods/           # 方法签名（每源码文件一个 JSON）
├── calls/             # 调用关系（每源码文件一个 JSON）
├── entries.json       # 入口点汇总（API 路由 + 定时任务 + CLI）
├── pending.json       # 待 AI 处理的事项
└── filters.json       # 噪声过滤规则（可选）
```

> **建议**：将 `.code-compass/` 目录加入项目 `.gitignore`，索引在本地构建。

## 与其他 RDD Skill 的集成

### CTO 模式集成

**Phase 1 "理解项目现状"**：
```
进入 Phase 1 → 自动执行 /understand → 获得项目上下文摘要
→ 读取 requirement.md 理解需求
→ 基于上下文摘要 + 需求，执行分级分析
```

### DEV 模式集成

**任务分析阶段**：
```
进入任务分析 → 自动执行 /understand 建立全局上下文
→ 基于上下文执行 /navigate 定位目标代码
→ 如需理解流程，执行 /trace
→ 如需评估影响，执行 /impact
→ 完成上下文建立后，开始任务拆分
```

### 集成调用示例

RDD Skill 在关键阶段应生成如下调用：

**CTO Phase 1**：
```
我将先执行 /understand 建立项目上下文。
[执行 /understand 指令]
基于以上项目上下文，我现在开始理解需求...
```

**DEV 任务分析**：
```
首先执行 /understand 建立项目上下文。
[执行 /understand 指令]
现在执行 /navigate 定位需要修改的代码。
[执行 /navigate <目标功能>]
基于以上分析，开始任务拆分...
```

## 路由规则

1. **明确指令**（`/understand`、`/navigate`、`/trace`、`/impact`、`/map`、`/readme`）→ 直接执行对应功能
2. **自然语言关键词** → 匹配最相关的功能：
   - 包含"理解"、"上下文"、"项目概览" → `/understand`
   - 包含"定位"、"找"、"哪个文件"、"在哪里" → `/navigate`
   - 包含"追踪"、"调用链"、"流程" → `/trace`
   - 包含"影响"、"改动"、"改哪里" → `/impact`
   - 包含"索引"、"构建"、"扫描" → `/map`
   - 包含"文档"、"readme" → `/readme`
3. **无法确定** → 向用户确认
4. **RDD Skill 关键阶段** → 按自动触发规则执行

## 快速上手路径

### 首次使用

1. 执行 `/map` 构建代码索引
2. 执行 `/understand` 查看项目概览
3. 根据需要使用 `/navigate`、`/trace`、`/impact`

### 日常使用

1. 根据任务选择合适指令
2. 基于指令结果进行下一步操作
3. 如发现索引过期，执行 `/map --refresh`

### 与其他 Skill 协作

1. 进入其他 RDD Skill 的关键阶段
2. Skill 自动调用 `/understand` 建立上下文
3. 基于上下文继续 Skill 的工作流程
