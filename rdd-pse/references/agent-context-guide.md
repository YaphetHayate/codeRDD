# CLAUDE.md / AGENT.md 编写指南

> 本文档定义了面向 AI agent 的项目上下文文件的编写标准和模板。
>
> CLAUDE.md 和 AGENT.md 是同类文件——都是为了让 AI agent 快速理解项目全貌而编写的上下文文档。两者使用相同的结构，文件名取决于目标 agent 平台（Claude Code 使用 `CLAUDE.md`，其他 agent 平台可能使用 `AGENT.md`）。

---

## 设计目标

AI agent 阅读此文件后，应该能够：

1. **知道项目是干嘛的** — 一句话定位
2. **知道用什么技术** — 语言、框架、关键依赖
3. **知道代码怎么组织的** — 目录结构和模块职责
4. **知道怎么写代码** — 命名规范、文件组织、lint 规则
5. **知道怎么运行和测试** — 常用命令速查
6. **知道有什么坑** — 历史遗留问题、不要碰的禁区

## 编写要点

### 项目概述

- 一句话定位要**准确具体**，AI agent 需要用这个信息来判断"我能做什么"
- 如果项目有独特的术语或概念（如本项目中的 RDD、归档、流转），在此解释

### 技术栈

- 必须标注**具体的测试框架和 lint 工具**，因为 agent 写代码时需要知道用什么工具
- 标注**包管理器**（npm/yarn/pnpm），因为 agent 需要知道用什么命令安装依赖
- 如果有 monorepo，标注 monorepo 管理工具（nx/turborepo/lerna）

### 目录结构

- 每个目录都要有**功能性描述**（干什么的），不只是罗列路径
- AI agent 需要知道"我要写个新组件放哪？""测试写在哪？"这类问题的答案
- 标注**不要碰的目录**（如自动生成的、第三方 vendor 目录）

### 编码约定

- 从实际代码中**推断**，不要凭空写"遵循最佳实践"
- 阅读 3-5 个源文件，提取共性的命名风格和组织方式
- 如果项目有 `.editorconfig` / `.prettierrc` / `.eslintrc`，直接引用它们的规则
- **注释语言**很重要——agent 需要知道加注释时用哪种语言

### 命令速查

- 命令必须**可以直接复制运行**，不要含占位符如 `<branch-name>`
- 如果命令有常用参数，给出完整示例
- 排序：安装 → 开发 → 构建 → 测试 → lint → 部署

### 关键模式

- 这是 agent 能"像老手一样写代码"的关键
- 描述 2-4 个项目中的常见模式：
  - 怎么定义一个新的 API 端点？
  - 怎么添加一个新的 UI 组件？
  - 怎么处理错误？
  - 怎么调用数据库？
- 每个模式给出**一个简短的代码示例**（3-5 行即可）

### 注意事项

- **不要碰的**：明确列出 agent 的禁区（如本项目各角色的文件白名单）
- **容易踩的坑**：从代码中发现的陷阱（如自动生成代码、特殊的启动顺序）
- **历史遗留**：标注已知的技术债和暂未迁移的部分

## 特殊目录信息

如果项目存在以下目录，务必在 CLAUDE.md / AGENT.md 中说明：

| 目录 | 在文档中的说明 |
|------|--------------|
| `.rdd/` | RDD 工作流归档目录，各角色文档存放处 |
| `.claude/` | Claude Code 配置目录 |
| `.opencode/` | Opencode 配置目录 |
| `.github/` | CI/CD 工作流 |
| `node_modules/` | **忽略，不写入文档** |
| `__pycache__/` | **忽略，不写入文档** |

## 生成流程

1. **先完成项目分析**（`project-analysis.md`）→ 所有信息来自分析阶段
2. **确定文件名**：如果有 `.claude/` 目录 → 生成 `CLAUDE.md`；如果有 `.opencode/` 目录 → 同时生成 `AGENT.md`；用户可指定
3. **按模板填充**，不确定的内容标注 TODO 并询问用户
4. **呈现初稿给用户确认**，逐节过而不是整篇抛
5. **确认后写入文件**

---

## 更新流程

当项目发生重大变化时（新增模块、技术栈升级、目录重组），PSE 应主动建议更新：

1. 重新执行项目分析
2. 对比现有 CLAUDE.md / AGENT.md
3. 标注差异，用户确认后更新
4. 在文件末尾追加更新日志（可选）：

```markdown
## 更新日志

| 日期 | 变化 |
|------|------|
| YYYY-MM-DD | [变化描述] |
```

## 风格要求

- **用中文写** — 除非项目约定为全英文
- **给 agent 看的，不是给人看的** — 可以比 README 更技术细节、更"干"
- **以指令口吻写** — 如"你需要知道..."而不是"开发者需要知道..."
- **代码示例简洁** — 3-5 行足够说明模式，不要贴大段代码
- **避免推测** — 不确定的标注 `[待确认]`，不要编造
