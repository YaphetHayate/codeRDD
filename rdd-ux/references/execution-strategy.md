# 工作模式策略

本文件定义 UX Skill 三种工作模式的详细执行流程、输入输出规则和模式切换条件。

> 输入处理（路由发现）的完整优先级判定见 `../SKILL.md` 的「输入处理」章节。本文件只定义确定工作模式后的执行细节。

---

## 通用归档流程（Phase 4）

三种模式的 Phase 4 归档流程完全一致，统一在此定义，各模式章节不再重复：

1. 按 `../references/self-check.md` 完成交付前自检
2. 将设计规格写入 `design/{需求文件名}-ux.md`（需求文件名从 task.md 的"需求文件"字段获取，去掉 `.md` 后缀）
3. 设置文档 `## 流转控制`：当前责任人 = DEV，状态 = active
4. 更新 task.md 路由总览：已完成需求的行，当前责任人改为 DEV，关联设计文档填入实际路径
   - 旧格式（✅⬜ 状态表）：UX 列从 ⬜ → ✅
5. 更新 `.rdd/design-system/` 累积资产（详见 SKILL.md「设计系统累积视角」）：
   - 新增的 Primitive/Semantic Token 追加到 `tokens.md`
   - 新增的组件追加到 `components.md`
   - 目录不存在时创建并写入本次设计的基础 Token 和组件清单
6. 如有 Phase 2.5 视觉稿产物（`mockups/final.html` 和 `mockups/images/reference.png`），将路径写入设计规格文档的「视觉稿参考」章节
7. 呈现给用户确认后，按 `../../rdd-engine/references/transition-guide.md` 的**上游协议 4 步硬流程**执行角色交接（next → 推荐 → 确认 → handoff packet）

## 翻译者模式（Translator）

### 触发条件

用户提供了参考图（PNG/JPG 文件或 URL），要求基于参考图实现前端界面。

### 输入

- 参考图（1-N 张）
- requirement.md（如有）
- 用户口述的补充说明（如有）

### 执行流程

```
Phase 1: 项目视觉上下文理解
  ├── 了解项目前端技术栈
  ├── 了解项目现有视觉风格
  └── 确认需求范围

Phase 2: 视觉分析
  ├── 加载 references/visual-analysis-guide.md
  ├── 对每张参考图执行五步视觉分解法
  │   ├── Step 1: 整体布局识别
  │   ├── Step 2: 设计 Token 提取
  │   ├── Step 3: 组件识别与分类
  │   ├── Step 4: 交互状态推断
  │   └── Step 5: 信息层级梳理
  ├── 多张参考图时的合并策略：
  │   ├── 提取共用的设计系统（色彩、字体、间距）
  │   ├── 每张图对应不同页面/状态的组件规格
  │   └── 识别图间的不一致，向用户确认以哪个为准
  └── 补充参考图未覆盖的部分
      ├── 标注哪些内容来自参考图
      ├── 标注哪些内容由 UX 补充推断
      └── 补充内容需与用户确认

Phase 3: 设计规格产出
  ├── 加载 references/spec-template.md
  ├── 将分析结果格式化为设计规格
  └── 呈现给用户确认

Phase 4: 通用归档流程（见上文）
```

### 输出

- `design/{name}-ux.md` — 结构化设计规格文档

### 分析精度说明

对视觉分析结果采用置信度标注：

| 置信度 | 含义 | DEV 处理建议 |
|--------|------|-------------|
| 🟢 高 | 参考图中明确可见的参数 | 直接使用 |
| 🟡 中 | 通过上下文推断的参数 | 可微调 |
| 🔴 低 | 参考图模糊或被遮挡的参数 | 建议与用户确认 |
| ✦ | UX 补充（参考图未覆盖） | 按设计规范使用 |

## 创作者模式（Creator）

### 触发条件

用户只提供业务需求，没有视觉参考，需要 UX 从零开始设计。

### 输入

- requirement.md
- 用户口述的需求说明
- 项目现有代码和风格约束

### 执行流程

```
Phase 1: 项目视觉上下文理解
  ├── 了解项目前端技术栈
  ├── 了解项目现有视觉风格
  │   ├── 如果项目有设计系统 → 严格遵循
  │   ├── 如果项目有部分样式 → 参考并保持一致
  │   └── 如果项目无前端代码 → 建立完整的设计系统
  └── 确认需求范围

Phase 2: 设计创建
  ├── 加载 references/design-methodology.md
  ├── 执行七步设计法
  │   ├── Step 1: 需求理解与场景定义
  │   ├── Step 2: 信息架构
  │   ├── Step 3: 布局设计 ← 关键决策点，需与用户讨论
  │   ├── Step 4: 视觉系统建立 ← 关键决策点，需与用户讨论
  │   ├── Step 5: 组件设计
  │   ├── Step 6: 交互设计 ← 关键决策点，需与用户讨论
  │   └── Step 7: 一致性检查
  └── 关键决策点讨论
      ├── 每个关键决策给 2-3 个选项
      ├── 每个选项说明利弊
      └── UX 给出推荐 + 理由，用户最终决定

Phase 3: 设计规格产出
  ├── 加载 references/spec-template.md
  ├── 将设计结果格式化为设计规格
  └── 呈现给用户确认

Phase 4: 通用归档流程（见上文）
```

### 输出

- `design/{name}-ux.md` — 结构化设计规格文档

### 设计决策记录要求

创作者模式下，所有设计决策必须在规格文档的"设计决策记录"章节中体现：

```
| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 导航模式 | 侧边栏 / 顶部 / 混合 | 侧边栏 | 功能模块多（6+），顶部导航空间不足 |
| 主色 | #3B82F6 / #10B981 / #8B5CF6 | #3B82F6 | 偏专业/工具感，蓝色系更合适 |
```

## 混合模式（Hybrid）

### 触发条件

用户同时提供了参考图和业务需求，需要先分析参考图再补充设计。

### 执行流程

```
Phase 1: 项目视觉上下文理解（同上）

Phase 2: 混合设计
  ├── 2A: 翻译者子流程
  │   ├── 分析参考图，提取视觉系统（色彩、字体、间距）
  │   ├── 提取参考图覆盖的组件和布局
  │   └── 标注参考图的边界（哪些没覆盖到）
  ├── 2B: 创作者子流程（针对参考图未覆盖部分）
  │   ├── 基于提取的视觉系统，保持风格一致
  │   ├── 为需求中参考图未覆盖的页面/组件设计
  │   └── 补充所有交互状态
  └── 2C: 合并
      ├── 确保翻译部分和创作部分的视觉系统一致
      └── 统一输出一份设计规格

Phase 3: 设计规格产出
  ├── 加载 references/spec-template.md
  ├── 将设计结果格式化为设计规格
  └── 呈现给用户确认

Phase 4: 通用归档流程（见上文）
```

### 混合模式的核心原则

**翻译部分是约束，创作部分是补充。** 参考图提取的视觉系统是"硬约束"——创作部分必须在这个框架内设计，不能偏离。

参考图与需求冲突时，按以下三级裁决处理，避免所有冲突都中断询问用户：

**第一级（默认规则，UX 直接执行不询问）：**

| 冲突维度 | 默认裁决 | 理由 |
|---------|---------|------|
| 视觉 Token（色彩/字体/间距） | 参考图胜 | 视觉系统是参考图的核心价值 |
| 布局结构（参考图已覆盖的页面） | 参考图胜 | 用户明确提供了视觉意图 |
| 布局结构（参考图未覆盖的页面） | 需求胜 | 参考图无约束力 |
| 组件状态（参考图可见状态） | 参考图胜 | |
| 组件状态（hover/loading/error 等推断态） | 设计系统胜 | 参考图未展示 |
| 信息密度/内容量 | 需求胜 | 参考图数据是样品 |
| 可访问性（对比度/焦点/尺寸） | 可访问性胜 | 硬性合规，不可妥协 |

**第二级（UX 自行决定，但必须在设计决策记录中说明理由）：**

- 参考图视觉与需求"产品气质"明显不符（如参考图活泼但需求是金融工具）
- 参考图布局在需求目标设备上不可行

**第三级（升级用户裁决）：**

- 参考图与需求核心目标冲突（如参考图无搜索功能，但需求核心是搜索）
- 可访问性与参考图视觉冲突，且调整会显著偏离参考图
- 多张参考图之间互相矛盾

升级时的话术模板：

```
参考图与需求在 [维度] 上存在冲突：
  - 参考图：[描述]
  - 需求：[描述]
  - 我的默认裁决：[按第一级规则]，理由 [X]
  - 如果你希望覆盖默认，告诉我优先 [参考图/需求]
```
