# Skill 辅助工作流

## 背景

当前 RDD 工作流中，CTO 和 DEV 的专业能力覆盖的是通用软件工程（架构设计、代码实现），但在遇到特定领域任务（如像素美术、UX 设计、动画等）时，缺乏获取领域专业知识的途径。实际项目中已经出现了因此导致产出质量不达标的问题（像素办公室场景反复重绘仍不满意），而项目内已有对应的 skill（如 pixel-art-sprites）却未被利用。

## 需求列表

### 需求 1：创建统一 skill 索引文件

- **描述**：在项目根目录创建一份统一的 skill 索引文件，列出所有可用的 skill 及其擅长的领域标签，供 CTO 和 DEV 查询匹配
- **验收标准**：
  - 索引文件存在于约定路径，CTO 和 DEV 都知道去哪里读
  - 每个条目包含 skill 名称、触发关键词/领域标签、简要能力描述
  - CTO Phase 1 需求分级时、DEV 任务分析阶段时，能够根据需求的领域特征匹配到对应 skill
- **优先级**：高

### 需求 2：CTO 增加 skill 辅助设计环节

- **描述**：在 CTO 的需求分级阶段（Phase 1），增加领域识别和 skill 匹配步骤。当需求涉及超出通用软件工程的领域时，CTO 主动加载对应 skill 获取领域知识，并将 skill 的指导融入设计文档
- **验收标准**：
  - CTO 在 Phase 1 分级时，对每个需求标注领域标签
  - 能匹配到 skill 的需求，设计文档中包含 skill 提供的领域专业指导（如像素美术的调色板策略、UX 的布局原则等）
  - 匹配不到 skill 的领域，CTO 能调用 find-skill 尝试发现可用技能
  - find-skill 也找不到时，在设计文档中标注"领域知识缺口"，提示 DEV 注意
- **优先级**：高
- **影响范围**：rdd-cto/SKILL.md

### 需求 3：DEV 增加 skill 辅助实现环节

- **描述**：在 DEV 的任务分析阶段，增加领域识别和 skill 匹配步骤。当实现任务涉及特定领域时，DEV 主动加载对应 skill 获取实现指导，在编码过程中参考 skill 的专业建议
- **验收标准**：
  - DEV 在任务分析阶段对每个任务标注领域标签
  - 能匹配到 skill 的任务，实现过程中参考 skill 的领域指导（如像素画的绘制技法、动画帧的设计原则等）
  - 匹配不到 skill 的领域，DEV 能调用 find-skill 尝试发现可用技能
  - find-skill 也找不到时，向用户报告领域知识缺口，协商处理方式
- **优先级**：高
- **影响范围**：rdd-dev/SKILL.md

## 关键约束

- find-skill skill 视为已确定会存在，CTO 和 DEV 的流程设计中应默认其可用
- skill 索引文件是单一来源（single source of truth），CTO 和 DEV 都读取同一份
- 不改变 CTO 和 DEV 的核心工作流结构，只在现有流程节点中插入 skill 匹配环节
- skill 辅助是"咨询"模式：CTO/DEV 吸收 skill 的领域知识来提升自己的产出质量，不把整个子任务委托出去

## 讨论记录

- 起因：像素办公室场景经过多轮迭代仍不满意，根因是 CTO/DEV 把像素美术当普通工程任务处理
- 确定采用咨询式而非委托式：CTO/DEV 自己执行，skill 提供领域知识指导
- 确定使用统一 skill 索引文件（方案 B），避免多处维护
- 确定配套 find-skill skill，作为"索引中无匹配"时的兜底手段
