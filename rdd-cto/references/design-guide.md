# 技术方向设计指南

本文件是 CTO 各场景流程的**格式与模板参考库**。按需查阅，不按顺序通读。

---

## 决策点话术

每个决策点按固定结构表达：

```
"需求 X 需要解决 Y 问题。我建议 [方案]，因为 [理由]。
对于 [不适用场景]，可以 [兜底策略]。你觉得这个方向可以吗？"
```

---

推荐必须同时考虑三个维度，缺一不可：

- **业务匹配**：方案与当前业务场景的契合度
- **现有框架**：方案与项目已有代码、技术栈的兼容性

## 技术方向文档模板

主体文档，1 页纸以内。决策记录与风险提示独立为附带产物。

```markdown
---
requirement_id: req-xxx
priority: 高
role: cto
status: active
---

# 需求标题 — 技术方向文档

## 需求概述
一句话说清要解决什么。

## 变更地图

project-root/
├── backend/app/
│   ├── models/xxx.py               [修改] 字段扩展说明
│   └── api/xxx.py                  [修改] 处理逻辑说明
├── frontend/src/
│   ├── types/index.ts              [修改] 类型新增说明
│   └── components/xxx.tsx          [修改] 映射/渲染说明

[新增] 0 | [修改] N | [删除] N | 无新增依赖

## 技术方案
每项一句话，不做展开：

- **存储**：xxx
- **落盘时机**：xxx
- **向后兼容**：xxx
- **字段命名**：xxx

> 对方案有疑问或需了解决策理由，请查阅附带产物 `*-decisions.md`。
```

附带产物文件 `*-decisions.md`：

```
# 决策记录

| # | 决策点 | 备选 | 选择 | 理由 |
|---|--------|------|------|------|
| 1 | 决策点描述 | A: xxx / B: xxx | B | 理由简述 |

# 风险提示

| 风险 | 影响 | 应对 | 级别 |
|------|------|------|------|
| 风险描述 | 影响简述 | 应对方向 | P1/P2/P3 |
```

> **注意**：变更地图用树状图标注每个文件的操作类型（[修改]/[新增]/[删除]），一目了然。技术方案每项只写一句话结论，不展开论证。决策记录和风险提示独立为同名 `*-decisions.md` 文件，供有疑问时查阅。

## 分级结果呈现格式

```
需求分级评估：

┌──────────────────┬──────┬──────────────────────────────────┐
│  需求              │ 等级  │ 理由                              │
├──────────────────┼──────┼──────────────────────────────────┤
│  需求 1：XXX       │  L1  │ 2 个文件，无选型，无外部依赖        │
│  需求 2：YYY       │  L2  │ 跨 3 个 API 文件 + 数据模型变更     │
│  需求 3：ZZZ       │  L3  │ 需引入消息队列做选型决策             │
└──────────────────┴──────┴──────────────────────────────────┘
```

## L1 快速结论格式

每个 L1 需求用以下格式输出：

```
需求：[标题] (L1)
  可行性：✅ 可行  |  风险：🟢 低
  影响范围：[涉及的 2-3 个文件或模块]
  备注：[如有需要注意的点，一句话说明；没有则省略]
```
