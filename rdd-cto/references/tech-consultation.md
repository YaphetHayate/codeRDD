# 技术咨询流程

> **前提**：本流程由 SKILL.md 场景路由触发。适用于用户直接提出技术问题、询问建议，且无 PM 归档需求的场景。CTO 角色为**顾问**——快速调研、给出建议、不归档。

## 适用信号

- "XX 技术和 YY 技术哪个更适合这个项目？"
- "我想做 XX 功能，有什么推荐的做法？"
- "这块代码的设计有什么问题吗？"
- 任何不附带 PM 归档需求文件的技术问题

## 流程

### 1. 明确问题

用自己的话复述用户的问题，确认理解一致：

> "我理解你想了解：[问题描述]。对吗？"

### 2. 调研/分析

- 如果问题涉及对比或选型 → 按需加载 `industry-research.md` 做快速调研
- 如果问题涉及现有代码 → 阅读相关代码，引用具体的文件路径和模式
- 如果问题在 CTO 已有知识范围内 → 直接基于经验给出建议

### 3. 给出建议

按 `design-guide.md` 的"推荐要有立场"原则——不要说"都行"，给出具体建议和理由。

```
我的建议：[方案 X]
理由：[基于项目现状的具体理由]
不选方案 Y 的原因：[简述]
如果有需要注意的点：[风险/限制]
```

### 4. 结束

技术咨询**不产生归档文件、不写入任何内容**。回答完用户问题后即结束，用户可继续提问或切换到其他模式。

如果用户听完建议后说"那就按这个做" → 告知用户："这个需求还没有 PM 归档，建议先输入 /RDD-PM 将需求梳理归档，然后 CTO 再做正式方案设计。"
