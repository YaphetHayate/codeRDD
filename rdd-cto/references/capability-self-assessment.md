# 能力自评

在需求分级之后、领域识别与 Skill 匹配之前执行。评估 CTO 自身是否有能力完成当前需求的设计，决定是否需要借助领域 Skill 的辅助。

---

## 自评流程

```
能力自评流程：

1. 判断需求领域
  │
  ├── 通用工程类需求（架构设计、API 设计、数据模型、性能优化等）
  │   → 属于 CTO 核心能力，标记"能力充足"，跳到领域识别与 Skill 匹配
  │
  └── 涉及特定领域（图形算法、加密协议、特定框架深度使用、
      特定行业规范等）
      → 自评：是否有足够领域知识出设计方案？
      ├── 有把握 → 跳到领域识别与 Skill 匹配
      └── 不确定/无 → 读取 rdd-cto/skills/index.md（已学习 skill 缓存）匹配
          ├── 命中 → 读取 skill SKILL.md，提取领域知识融入设计
          └── 未命中 → 调用 find-skill 搜索相关领域 skill
          ├── 找到 → 读取 skill SKILL.md，提取领域知识融入设计
          │         → 将条目追加到 rdd-cto/skills/index.md（避免重复搜索）
          │         → 并建议用户将新发现的 skill 补充到 rdd-engine/skill-registry.md
          └── 未找到 → 在技术方向文档中标注能力缺口，向用户说明
```

## 自评约束

只对非通用工程需求做自评。常规的架构设计、API 设计、数据模型设计属于 CTO 核心能力，不需要触发自评。目的是避免每个任务都触发 find-skill 搜索造成不必要开销。
