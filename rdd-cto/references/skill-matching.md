# 领域识别与 Skill 匹配

对需求分级中标注了领域标签（非"通用工程"）的需求，执行 Skill 匹配，将领域知识融入设计过程。

---

## 领域标签提取规则

阅读需求描述和验收标准，判断是否涉及以下方向（不限于）：

- 视觉设计（UI/UX、布局、配色、交互、组件规范、响应式）→ 匹配 **rdd-ux** skill。CTO 在技术方向文档中标注视觉/交互由 UX 负责（→ design/{name}-ux.md），提醒 DEV 实现时参考 UX 规格。
  > 注：UX 的启动由 task.md 角色参与计划决定，CTO 不做门控判断。
- 像素美术（像素画、精灵图、调色板、sprite）→ 匹配 pixel-art-sprites
- 特定渲染技术（Canvas、WebGL、SVG）
- 数据可视化
- 特定算法（路径规划、物理模拟）
- 其他需要专业领域知识的方向

不涉及特定领域的标为"通用工程（无）"，跳过 Skill 匹配。

## 分级结果表格式

分级结果表中增加"领域标签"列：

```
┌──────────────────┬──────┬──────────────────┬──────────────────────────────┐

```

## 匹配流程

```
对每个有领域标签的需求：
  │
  ├── 读取 rdd-engine/skill-registry.md
  │
  ├── 将需求的领域标签与 registry 中每个 skill 的领域标签做关键词匹配
  │   （标签之间有交集即视为匹配）
  │
  ├── 匹配到 skill
  │   ├── 读取该 skill 的 SKILL.md
  │   ├── 提取与当前需求相关的领域知识
  │   └── 将领域知识作为设计参考，融入后续深度分析和设计方案
  │
  └── 未匹配到 skill
      ├── 读取 rdd-cto/skills/index.md（已学习 skill 缓存）再次匹配
      │   ├── 命中 → 按上述流程读取并融入
      │   └── 未命中 → 调用 find-skill skill，描述当前需求的领域特征
      │   ├── find-skill 找到 → 按上述流程读取并融入
      │   │     将条目追加到 rdd-cto/skills/index.md（避免重复搜索）
      │   │     并建议用户将新发现的 skill 补充到 rdd-engine/skill-registry.md
      │   └── find-skill 未找到 / find-skill 不可用
      │         在技术方向文档中标注：
      │         "⚠️ 领域知识缺口：本需求涉及 [领域] 但无对应 skill 辅助。
      │          DEV 实现时需注意此领域下的专业要求。"
      │         并在分析汇总中向用户主动说明
```
