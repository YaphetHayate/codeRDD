# 领域识别与 Skill 匹配

对需求分级中标注了领域标签（非"通用工程"）的需求，执行 Skill 匹配，将领域知识融入设计过程。

---

## 领域标签提取规则

阅读需求描述和验收标准，判断是否涉及以下方向（不限于）：

- 视觉设计（UI/UX、布局、配色、交互、组件规范、响应式）→ 匹配 **rdd-ux** skill。CTO 在设计文档中标注视觉/交互由 UX 负责（→ ux/{name}.md），提醒 DEV 实现时参考 UX 规格。
  > 注：UX 的启动由 task.md 角色参与计划决定，CTO 不做门控判断。
- 像素美术（像素画、精灵图、调色板、sprite）→ 匹配 pixel-art-sprites
- 特定渲染技术（Canvas、WebGL、SVG）
- 数据可视化
- 特定算法（路径规划、物理模拟）
- 其他需要专业领域知识的方向

不涉及特定领域的标为"通用工程（无）"，跳过 Skill 匹配。

## 分级结果表格式

分级结果表中增加"领域标签"列：

```
┌──────────────────┬──────┬──────────────────┬──────────────────────────────┐
│  需求              │ 等级  │ 理由              │ 领域标签                      │
├──────────────────┼──────┼──────────────────┼──────────────────────────────┤
│  需求 1：XXX       │  L1  │ ...              │ 通用工程（无）                 │
│  需求 2：YYY       │  L2  │ ...              │ 像素美术, Canvas 渲染          │
└──────────────────┴──────┴──────────────────┴──────────────────────────────┘
```

## 匹配流程

```
对每个有领域标签的需求：
  │
  ├── 调用 rdd-engine `/skill-manager query`
  │   传入 role=CTO、需求标题、领域标签、需要的设计能力
  │
  ├── skill-manager 推荐 skill
  │   ├── 读取该 skill 的 SKILL.md
  │   ├── 提取与当前需求相关的领域知识和使用约束
  │   ├── 将领域知识作为设计参考，融入后续深度分析和设计方案
  │   └── 设计完成后调用 rdd-engine `/skill-manager record-use` 记录使用情况
  │
  └── skill-manager 无匹配
      ├── 在设计文档中标注：
      │   "⚠️ 领域知识缺口：本需求涉及 [领域] 但无对应 skill 辅助。
      │    DEV 实现时需注意此领域下的专业要求。"
      └── 在分析汇总中向用户主动说明
```
