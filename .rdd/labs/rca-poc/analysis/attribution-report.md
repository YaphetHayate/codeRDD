## 1. 判据一:机械结构(架构能否运转)

**结论:通过。** 证据:

- **循环运转**:goal+workflow 组合下,Manager 每轮"读 state→扇出→整合→落盘→read-back"闭环在 11 次运行中零结构故障;轮间认知重建(断点恢复语义)在 L1/L2/L3 反复生效(每轮首读三文件,与落盘一致)。
- **停止语义**:三种停止条件全部实际触发过且行为正确——条件 1(pm-001 0.90/L3、task1-2100 0.82)、条件 2(pilot task1,预算保留如实落档)、条件 3(task6-1800/task2-1330,候选穷尽)。"与破案成功解耦"被严格遵守:**0 例硬编结论**。
- **回调契约**:全部 worker 回调 schema 有效(L1 5/5,L2 pilot 7/7,L2 批量 10/10,L3 3/3 = 25/25);citations 格式偏差仅 L1 Round 1 出现(prompt 补格式说明后 22/22 合规,零 Manager 归一)。
- **诚实性机制生效**:needs_review 标记在 located+非 causal 结论上正确触发(task1-2100);基线的泛词假信号("CPU" 1 命中)被 located_needs_review 拦截;conf 0.6 未达标时如实软结案(pilot)。
- **降级路径**:未触发(goal+workflow 顺利);R7 素材互备兑现(L1 零外部依赖、OpenRCA 数据受阻期 L3/基线不受阻)。

**原语缺口(observations §1,7 项)**:核心两项——①无 append 原语(edit 替换语义损坏 JSONL ×2,靠 read-back 拦截,后以落盘脚本化规避;PowerShell 内联转义坑 ×2 同类);②workflow schema 子集无数值边界/pattern(confidence 范围靠 Manager 校验,citation 格式靠 prompt 约定)。其余:轮间恢复无引擎保障(靠 Manager 自觉)、无子代理文件 ACL(prompt 级边界,11 runs 零越界观测)、ralph 无轮内扇出(基线设计如此)。

## 2. 判据二:调查能力(架构能否调查)

**结论:通过(带口径注记)。** 证据:

- **可解性**:L1 1/1 located;L2 4/4 组件命中(真值组件名全部出现在结论文本,其中 2 案全部关键词命中);L3 1/1 located(10/13 关键词、0 误归因、2 条 causal 证据)。
- **调查纪律(超出预期的正面信号,observations §7.3)**:预注册判定标准(先定阈值再比对)、孪生对照推翻显眼数字(内存 98% 锚定免疫)、60s 采样夹逼、"无症状共存"判据、"[0,1] 域越界反推口径"、"自然实验"识别(hotfix 恢复先于数据干净的时序差)、行级身份匹配(ALTER 前行数=首个失败行 id)。

## 3. 判据三:增益归因(编排是否优于单体,归因于什么)

**结论:有增益,但增益有明确边界条件。**

### 3.1 增益证据

| 形态 | 编排臂 | 基线臂 | 差异 |
|------|--------|--------|------|
| L2(症状-根因解耦,4 案) | 组件命中 4/4 | **0/4** | 决定性 |
| L3(症状即根因机制) | located | located(同深度) | 无差异 |
| 结案行为(9 案) | 保守:3/4 软结案 | **过度自信:4/4 硬结案自评 causal 而 0/4 对** | 系统性 |

### 3.2 归因(增益来自哪里)

1. **扇出宽度的域级穷尽**(直接证据:task1-2100——基线全量 robust-z 扫描漏掉 IG01 JVM_CPULoad 事件线,编排臂的 JVM 专项 worker 捕获;单体单线调查受假设生成顺序制约);
2. **多 worker 独立交叉**(两案实证:w1 指标面与 w3 trace 梯度独立收敛 Mysql 层;L3 H1/H2 双 causal 独立支撑同一机制);
3. **Manager 整合层的口径裁决与置信度纪律**(L2 主因:基线以"症状机制解释"为根因锚(4/4 漂亮故事但组件全错),编排臂经"排除法+独占性判据"回到事件锚定;基线无交叉校验时"causal 自评"不可靠——4/4 自评 ≥0.8 而 0/4 命中)。

### 3.3 边界条件(何时无增益)

- **症状即根因机制的传统案例**(L3/pm-001):单体一轮即可走通,编排增益 ≈ 0(甚至轮次相同)——增益不来自"更聪明",来自**解耦形态下的口径裁决与穷尽**;
- **公平性备注**:基线的机制解释深度并不差(同秒差分/方向不对称/全网格配对/行级匹配等实验设计质量高),分歧本质是目标口径(解释症状 vs 找被标注事件),部分增益来自 Manager 层的口径启发式而非 worker 单兵能力;
- 样本量:n_L2=4, n_L3=1,不外推(单系统 Bank/单日;Telecom/Market 未验证)。

## 4. PoC 判定与建议

**判定:PoC 成功。** 三判据全部通过:机械结构可运转(零硬编、零结构故障、停止语义正确);调查能力成立(可解性 6/6 组件命中 + 纪律涌现);编排相对单体存在有边界条件的真实增益(L2 组件定位 4/4 vs 0/4),且增益来源可归因(扇出穷尽/独立交叉/口径裁决)而非不可解释的"更努力"。

**对"假设树驱动 Manager-Worker 编排"的定性结论**:该架构的价值不在"更强的单次推理",而在 ①域级穷尽扫描消除了单体假设生成的路径依赖;②多线独立交叉提供了单体不具备的自校验(对冲过度自信);③Manager 整合层可以承载"口径/判据"这类超推理的裁决规则。代价:轮次内扇出 token 成本 ≈3× 单体,复杂度集中在 Manager 协议(需 read-back 等防御性设计)。

**后续建议**(若立项完整验证):
1. **扩样**:Telecom/Market 系统 + 3-04 之外日期(检验独占事件锚定的跨域稳健性);
2. **口径策略固化**:Manager 协议加入"独占事件锚定优先,症状机制为辅"的双锚判据(L2 发现的直接产品);
3. **补盲区**:观测面加入进程级/池类指标与 retrans(四案 causal 末环阻断的共同原因);
4. **原语需求上抛**:append 原语、schema 数值边界/pattern、子代理文件 ACL(observations §1 清单)——编排可靠性的当前主要摩擦点;
5. **基线校准实验**:给 ralph 加"独占事件锚定"提示词后重跑 L2(分离"口径启发式"与"架构扇出"的增益贡献——本报告 3.2-③ 与 ①② 的相对权重待此实验闭合)。
