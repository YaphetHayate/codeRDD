# Skill 协同机制增强 — 设计文档

## 需求概述

两个强耦合需求合并设计：R1 解除 CTO 对 UX 的门控依赖，由 PM 在 task.md 中声明角色参与计划，CTO 和 UX 可并行启动；R2 为 CTO 和 UX 设计文档建立统一的 frontmatter 和需求覆盖映射，让 DEV 用一致的"接口层→内容层"方法解读。

## 需求覆盖映射

| 需求 ID | 本文档负责范围 | 对应章节 | 关联文档 |
|---------|--------------|---------|---------|
| 需求 1：PM 驱动的角色编排 | 角色参与计划格式、CTO/UX/DEV 入口条件变更 | 二、技术方案 改动 1-4 | — |
| 需求 2：设计文档接口层标准化 | 统一 frontmatter、需求覆盖映射、DEV 统一解读 | 二、技术方案 改动 4-6 | — |

## 二、技术方案

### 2.2 各文件具体改动

#### 改动 1：rdd-pm/references/task-template.md（R1）

**变更类型**：新增章节
**位置**：`## 总览` 之前
**内容**：新增 `## 角色参与计划` 表格

```markdown
## 角色参与计划

| 角色 | 参与状态 | 理由 |
|------|---------|------|
| CTO | ✅/⏭️ | [简要说明] |
| UX | ✅/⏭️ | [简要说明] |
| DEV | ✅/⏭️ | [简要说明] |
| QA | ✅/⏭️ | [简要说明] |
```

规则追加：

- PM 归档时必须填写此表格
- 角色参与计划与 Task 详情列保持一致：计划中 ⏭️ 的角色，所有 Task 该列也应为 ⏭️
- 历史归档中无此章节时，CTO/UX/DEV 回退到检查各 Task 详情列（向后兼容）

#### 改动 2：rdd-cto/SKILL.md（R1）

**变更类型**：修改 Phase 1.2 语义 + 更新输入处理

**a) Phase 1.2 领域标签规则**（当前 line 103 附近）

原文：
> 视觉设计（UI/UX、布局、配色、交互、组件规范、响应式）→ 匹配 **rdd-ux** skill，CTO 聚焦技术架构，视觉/交互层面的设计规格由 UX skill 负责

改为：
> 视觉设计（UI/UX、布局、配色、交互、组件规范、响应式）→ 匹配 **rdd-ux** skill。CTO 在设计文档中标注视觉/交互由 UX 负责（→ design/ux-spec.md），提醒 DEV 实现时参考 UX 规格。

在同一段落后新增：
> 注：UX 的启动由 task.md 角色参与计划决定，CTO 不做门控判断。

**b) 输入处理第 2 步**（当前 line 48-53 附近）

"读取 task.md 检查状态"中新增一条：
- 检查 task.md 是否包含"角色参与计划"章节
- 如包含且 UX 标记为 ✅，CTO 在设计文档中注明"UX 并行设计中"
- 如不包含（历史归档），按原流程处理

#### 改动 3：rdd-ux/SKILL.md（R1）

**变更类型**：更新输入处理 + 明确独立启动条件

**a) 优先级 B**（当前 line 51-56 附近）

在"筛选出 PM 已完成（✅）、UX 未完成（⬜）的 task"后新增：
> 检查 task.md 是否包含"角色参与计划"章节，UX 标记为 ✅参与则确认 UX 被期望参与。不包含时按原流程处理。

**b) Phase 1**（当前 line 74-87 附近）

"必须摸清"列表新增第 5 条：
> 5. **角色协同上下文** — 从 task.md 的角色参与计划中确认 CTO 是否也在并行工作。如 CTO ✅，归档时在 ux-spec.md 中引用 CTO 设计文档（反向引用）。

#### 改动 4：rdd-dev/SKILL.md（R1 + R2）

**变更类型**：修改 Mode 1 条件 + 新增统一文档解读方法

**a) Mode 1 进入条件**（当前 line 79）

原文：
> 如果存在 `design/` 子目录且 CTO 状态为 ✅，进入**设计引导模式**

改为：
> 如果存在 `design/` 子目录且 CTO 或 UX 任一状态为 ✅，进入**设计引导模式**

**b) 需求引导模式条件**（当前 line 80）

原文：
> 如果 CTO 状态为 ⏭️（跳过设计），进入**需求引导模式**

改为：
> 如果 CTO 和 UX 均为 ⏭️，进入**需求引导模式**

**c) 任务分析流程新增统一解读步骤**（当前 line 317 "通读文档"之后，"检查 ux-spec.md"之前）

```
├── 【统一文档解读】（design/ 目录存在时执行）
│   1. 读取所有设计文档 frontmatter，确认 role 和 status
│   2. 读取各文档的"需求覆盖映射"章节，定位每个需求对应的章节
│   3. 按角色分别进入正文：
│      CTO → 技术架构 / 接口 / 数据模型
│      UX → 视觉 Token / 组件规格 / 交互规范
│
│   仅存在 UX 规格而无 CTO 设计时：
│   - 视觉/交互层面严格遵循 UX 规格
│   - 技术实现方式由 DEV 基于 requirement.md 自行决定
│   - 按需求引导模式的自主决策范围执行
```

### 2.4 集成点描述

| 集成点 | 已有模块 | 调用关系 | 数据流向 | 时序约束 |
|--------|----------|----------|----------|----------|
| 角色参与计划写入 | rdd-pm/task-template.md | PM 归档时写入 → CTO/UX/DEV 启动时读取 | 单向（PM → consumers） | PM 必须先完成归档 |
| Frontmatter 读取 | rdd-dev 任务分析 | DEV 读取 CTO/UX 文档 frontmatter | 单向（docs → DEV） | 文档必须已归档 |
| 需求覆盖映射 | rdd-dev 统一解读 | DEV 读取映射表定位章节 | 单向（docs → DEV） | 文档必须已归档 |
| UX 反向引用 | rdd-ux/spec-template → rdd-cto/design-doc | UX 归档时引用 CTO 文档路径 | 单向引用 | CTO 文档需已存在或已知路径 |
