# 需求清单

## 背景

当前 RDD 工作流中，当用户报告 UI 问题或需要修改某个功能时，RDD agent（特别是 DEV）需要花费大量时间阅读代码来定位相关入口点和调用链。code-compass 已经提供了 `/map` 命令构建完整索引，但需要预先运行，成本较高。用户希望有一个更轻量级的命令，能根据业务关键词按需构建索引，帮助 RDD agent 快速定位相关代码。

## 需求列表

### 需求 1：code-compass 新增 `/trace` 命令

- **描述**：新增 `/trace` 命令，输入业务关键词，自动找到相关入口点并探索调用链，构建完整索引（方法签名、调用关系、入口点），将结果写入 entries.json、methods/、calls/ 目录（懒加载）
- **验收标准**：
  1. 命令格式为 `/trace <关键词>`，如 `/trace login`
  2. 自动识别项目框架（Flask、FastAPI、Express等），使用相应的路由模式识别策略找到入口点
  3. 如果无法识别框架或找不到入口点，回退到通用关键词搜索
  4. 从入口点出发，探索调用链（限制最大深度，如10层）
  5. 构建完整索引（方法签名、调用关系、入口点），将结果写入 entries.json、methods/、calls/ 目录
  6. 如果有多个入口点，返回所有入口点
  7. 如果项目使用多个框架，识别所有框架，按识别顺序探索
  8. 支持懒加载，不需要预先运行 `/map`
  9. 支持增量更新，检查相关文件是否变化，有变化才更新索引
  10. 输出格式为 JSON，面向 AI
- **优先级**：高
- **影响范围**：code-compass 技能
- **用户场景**：用户报告"登录按钮点击没反应" → DEV 运行 `/trace login` → 系统返回 POST /api/login 入口点和相关调用链 → DEV 快速定位相关代码
- **边界与异常**：关键词无匹配时返回空结果；调用链过深时限制最大深度；框架识别失败时回退到关键词搜索

### 需求 2：RDD-DEV 集成 `/trace` 命令

- **描述**：在 RDD-DEV 任务分析阶段自动调用 `/trace` 命令，帮助 DEV 快速定位相关代码
- **验收标准**：
  1. RDD-DEV 的 SKILL.md 中任务分析阶段包含自动调用 `/trace` 的步骤
  2. 调用时机为：DEV 分析任务时，根据需求关键词自动调用 `/trace`
  3. 调用结果用于指导后续的代码编写
- **优先级**：中
- **影响范围**：rdd-dev/SKILL.md
- **用户场景**：DEV 接到"修复登录功能"的任务 → 任务分析阶段自动调用 `/trace login` → 获取相关入口点和调用链 → 指导后续代码编写
- **边界与异常**：如果 `/trace` 命令不存在或执行失败，DEV 继续手动分析代码

## 关键约束

- `/trace` 命令支持懒加载，不需要预先运行 `/map`
- 输出格式以 JSON 为主，面向 AI
- 探索深度限制最大为 10 层
- 支持增量更新，检查相关文件是否变化，有变化才更新索引

## 讨论记录

- 用户希望 code-compass 能提供指导，帮助 RDD agent 定位相关代码
- 用户期望的命令格式为 `/trace <关键词>`
- 用户希望按需构建索引，而不是预先构建整个项目索引
- 用户希望输出格式以 JSON 为主，面向 AI
- 用户希望在 RDD-DEV 任务分析阶段自动调用 `/trace` 命令
