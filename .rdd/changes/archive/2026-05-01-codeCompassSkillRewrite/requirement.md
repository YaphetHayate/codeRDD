# code-compass SKILL.md 全面改版

## 背景

当前 SKILL.md 存在几个问题：
- **description** 偏技术罗列，没有传达核心价值（帮助人和 AI 快速理解项目）
- **功能描述** 混入了实现细节（存储结构、数据格式），不像面向用户的说明
- **缺少产物使用指南**：生成的 `.code-compass/` 目录该怎么用，没有概要说明
- **整体结构** 缺少"解决什么问题"的价值锚定，上来就是功能列表

## 需求列表

### 需求 1：重写 YAML description

- **描述**：重写 SKILL.md 头部的 description 字段，突出核心定位（项目代码理解加速器），简洁列出关键能力，优化触发关键词覆盖
- **验收标准**：
  - description 前 1-2 句传达核心价值主张，人能一眼理解这个 skill 干什么
  - 触发关键词覆盖：项目文档、代码分析、项目结构、readme、代码全景图、代码地图、调用关系、入口点、代码导航、理解项目、定位代码、评估改动影响
  - 不包含实现细节
- **优先级**：高
- **影响范围**：`code-compass/SKILL.md` YAML 头部

### 需求 2：重写 SKILL.md 主体结构

- **描述**：重新组织 SKILL.md 的章节结构，包含：价值定位（解决什么问题）、核心能力概览、产物使用方式（概要）、路由规则。功能描述从用户价值角度编写，不混入存储格式、数据结构等实现细节
- **验收标准**：
  - 有独立的"解决什么问题"章节，让读者理解 skill 的价值
  - `/map` 和 `/readme` 两个功能的描述聚焦于"能做什么"，不包含 JSON schema、文件路径编码规则等实现细节
  - 有"生成的产物与使用方式"章节，概要说明 `.code-compass/` 产物的结构和使用路径（读什么、怎么导航），不重复参考文件中的详细格式定义
  - 概要中标注"详细格式见 `references/map/map.md`"，引导 agent 按需读取
  - 路由规则保留但精简
- **优先级**：高
- **影响范围**：`code-compass/SKILL.md` 主体内容
- **边界与异常**：此次只改 SKILL.md，不动 `references/` 下的参考文件

### 需求 3：同步更新 evals.json

- **描述**：根据新的 description 和触发关键词，更新 evals.json 中的测试用例，确保覆盖新的触发场景
- **验收标准**：
  - 现有 eval 用例的 expected_output 与新描述一致
  - 补充"理解项目"、"定位代码"、"评估改动影响"等新关键词对应的 eval 用例
- **优先级**：中
- **依赖关系**：依赖需求 1、2 完成后更新
- **影响范围**：`code-compass/evals/evals.json`

## 关键约束

- SKILL.md 是 AI Agent 加载 skill 时首先读取的文件，内容必须**精炼**——足够理解 skill 能力和路由方式，但不应该成为大文件
- 产物使用说明在 SKILL.md 中只放概要（5 行以内的快速上手路径），详细格式和数据定义留在 `references/map/map.md`
- 只修改 SKILL.md 和 evals.json，不动 references 下的文件

## 讨论记录

- 确认核心定位：项目代码理解加速器，一次构建、按需查询
- 确认使用说明分层策略：SKILL.md 放概要，references 放详细
- 允许大改，不保留现有结构框架

## 评估结论

**推荐做。** SKILL.md 是 skill 的入口文件，直接决定 AI Agent 能否正确理解和触发功能。改动范围小（2 个文件），纯内容优化，无技术风险。
