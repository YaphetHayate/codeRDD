# PM 红线从黑名单改为白名单

## 背景

当前 RDD-PM SKILL.md 的模式边界采用"禁止做什么"的黑名单方式，需要枚举各种违规场景和对应的话术模板。这种方式的缺陷是：永远无法枚举完所有场景，导致约束存在漏洞（如用户直接下令"按你说的搞"时 PM 会绕过限制直接修改文件）。

CTO 和 QA 模式已经有"唯一的文件写入权限"白名单机制，PM 应对齐这个模式，从根本上解决约束不完整的问题。

## 需求列表

### 需求 1：红线改为白名单机制

- **描述**：将 PM SKILL.md 中"绝对禁止"的黑名单式约束，改为"唯一的文件写入权限"白名单式约束，与 CTO/QA 模式对齐
- **验收标准**：
  1. 红线章节包含"唯一的文件写入权限"段落，明确列出 PM 只能写 `RDD/changes/archive/.../requirement.md` 和 `task.md`
  2. "绝对禁止"三条黑名单规则删除或大幅精简，保留的核心精神由白名单自动覆盖
  3. 删除所有防御话术模板（"当用户试图让你直接改代码时..."、"用户暗示这很简单..."），替换为一条通用规则：任何超出白名单的写入操作，告知用户切换到 DEV 模式
- **优先级**：高
- **影响范围**：`rdd-pm/SKILL.md` 红线章节
- **边界与异常**：无

### 需求 2：references 文件创建确认

- **描述**：确认 `rdd-pm/references/` 下的三个文件（requirement-template.md、task-template.md、evaluation-guide.md）已正确创建且内容完整
- **验收标准**：三个 references 文件存在且内容与之前瘦身时产出的一致
- **优先级**：中

## 关键约束

- 改动只涉及 PM skill 自身的 SKILL.md，不影响其他 skill
- 白名单机制必须在视觉上醒目，确保模型不会忽略

## 讨论记录

- 核心决策：黑名单→白名单，无需枚举防御场景，通过路径白名单一劳永逸
- 防御话术砍成一条通用规则，不再维护场景列表
- 与 CTO/QA 的"唯一的文件写入权限"段落保持一致的表述风格
