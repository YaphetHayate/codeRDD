# UX ↔ 前端 DEV 反馈闭环（推迟）

- **描述**：当前 UX→DEV 为单向流水线，DEV 实施中若发现 UX 输出有问题（效果图与需求矛盾、资源决策不可行等）缺乏反馈校正机制。引入反馈闭环，DEV 可将问题回传 UX 修正。

- **验收标准**：
  1. 定义 DEV 向 UX 反馈的触发条件（什么情况下需要反馈而非自行修正）
  2. 定义反馈协议（DEV 反馈形式、UX 响应方式、迭代次数上限）
  3. task.md 中可追踪反馈轮次

- **优先级**：低（推迟）
- **来源细节**：用户观察——单向流水线导致错误规格被忠实执行后放大

- **影响范围**：RDD-DEV skill、RDD-UX skill、task.md 模板
- **边界与异常**：
  - **推迟理由**：需等需求 1（UX 重新定位）和需求 2（DEV 拆分）稳定跑通一个完整需求后，才有足够数据设计合理的反馈机制
  - 反馈不意味着 DEV 丧失自主权——DEV 仍可自行修正小问题，仅结构性/方向性问题回传
