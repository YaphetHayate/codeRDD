# UX 角色重新定位：从写规格到做视觉决策

- **描述**：将 RDD-UX skill 的职责从"输出代码级设计规格文档（颜色、字号、间距、组件结构等具体值）"改为"视觉决策 + 输出参考效果图"，不再教 DEV 怎么写代码，而是产出 DEV 能直观理解和参考的视觉方向。

- **验收标准**：
  1. RDD-UX skill 文件中移除所有关于"输出颜色具体值、字号、间距 px 值"等代码级规格的要求
  2. UX 输出物改为：参考效果图（可为 AI 生成）、资源决策清单（哪些用 CSS/代码实现，哪些用图片素材）、风格定调描述
  3. UX skill 中移除"不写任何代码"禁令中与画图/生成效果图冲突的部分（生成效果图本身是 UX 的代码调用工具行为，不属于业务代码）
  4. task.md 模板中 UX 列的职责说明同步更新

- **优先级**：高
- **来源细节**：用户实测反馈——UX 产出的代码级规格文档对 AI DEV 不直观、翻译成本高、错误放大

- **影响范围**：`rdd-ux/SKILL.md`、`rdd-ux/references/` 下各策略文件、`task.md` 模板
- **边界与异常**：
  - UX 不再负责决定具体像素值，但不排除在效果图中附带标注
  - UX 可调用图片生成工具，但图片生成能力本身由需求 4 独立提供
  - 若平台不支持多模态，UX 效果图需配套文字描述作为降级方案
