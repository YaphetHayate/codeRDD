# 优化 RDD 前端视觉链路

## 背景

当前 RDD 工作流中，前端视觉链路的产出质量差，体现在三个层面：

1. **UX 角色职责错位**：UX 输出代码级规格文档（颜色、字号、间距等具体值），对前端 DEV 不如一张图直观，对后端 DEV 完全无意义
2. **单向流水线无反馈**：UX→DEV 单向传递，DEV 忠实执行错误规格无纠错机制
3. **素材生成能力空白**：没有角色负责决策"图片 vs 代码"、没有角色负责生成高质量素材

实测验证表明，UX 介入后反而耗费更多时间/token，产出质量更差。

## 需求索引

| # | 文件 | 标题 | 优先级 |
|---|------|------|--------|
| 1 | uxRoleReposition.md | UX 角色重新定位：从写规格到做视觉决策 | 高 |
| 2 | devSplitFrontendBackend.md | DEV 拆分前后端角色 | 高 |
| 3 | uxDevFeedbackLoop.md | UX ↔ 前端 DEV 反馈闭环（推迟） | 低 |
| 4 | assetGenerationAbility.md | 图片/素材生成能力补充 | 中 |

## 关键约束

- 所有修改仅涉及 opencode skill 配置和 agent 定义，不涉及项目业务代码
- 需求 2 的可行性取决于 opencode 是否支持为不同 agent 指定不同模型
- 需求 4 不绑定 UX，作为独立工具/能力供所有角色调用

## 讨论记录

- 用户最初提议"把 UX 改成专门画图"，经讨论后明确痛点并非 UX 缺画图能力，而是当前设计→开发流水线角色职责错配
- 倾向方案：UX 从"写代码规格"改为"视觉决策 + 效果图"，DEV 按前后端拆分以接收适配各自能力的输入
- 反馈闭环需求（需求 3）建议推迟，等新 UX 和前端 DEV 跑通一个完整需求后再设计
- 素材生成（需求 4）建议独立于 UX，做成通用工具能力

## 风险评估

- 平台能力边界未知：opencode 是否支持 agent 级别模型配置、是否支持多模态
- 若不支持多模态，UX 输出效果图将无法被前端 DEV 消费，需降级方案
