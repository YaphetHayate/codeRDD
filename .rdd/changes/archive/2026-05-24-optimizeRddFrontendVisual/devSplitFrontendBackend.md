# DEV 拆分前后端角色

- **描述**：将当前统一的 DEV 角色拆分为"前端 DEV"和"后端 DEV"两个独立 agent/subagent，各自接收适配其能力的工作输入。前端 DEV 能理解视觉输入（效果图、设计参考），后端 DEV 处理 API、服务逻辑等纯文本推理任务。

- **验收标准**：
  1. 存在独立的前端 DEV agent/subagent 定义，输入可包含效果图/视觉参考
  2. 存在独立的后端 DEV agent/subagent 定义，输入仅文本（需求文档、CTO 接口设计）
  3. task.md 模板中 DEV 列拆分为"前端 DEV"和"后端 DEV"两列
  4. PM 在需求归档时可根据任务性质标记需要前端 DEV、后端 DEV 还是两者都需要

- **优先级**：高
- **来源细节**：前后端工作输入完全不同（前端需要视觉信息、后端不需要），当前混用导致前端缺信息、后端收噪声

- **影响范围**：DEV agent 定义、task.md 模板、PM 归档流程中的角色分配逻辑
- **边界与异常**：
  - 可行性依赖 opencode 是否支持为不同 agent 指定不同模型
  - 若不支持多模型，需降级为 DEV 内部通过指令自行区隔
  - 全栈任务（前端+后端）需两个任务 tracker 行或在 task 内标注两者都参与
