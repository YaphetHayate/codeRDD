# Task 模板

> **重要声明**：任务分工表为 PM 参考建议，CTO/DEV 可在设计阶段重新组织工作划分（合并、拆分、重排优先级），不受此表约束。

## 文件格式

```markdown
# Task Tracker

> 状态说明：✅ 完成 | ⬜ 待开始 | ⏭️ 跳过 | 🔄 进行中

## 角色参与计划

| 角色 | 参与状态 | 理由 |
|------|---------|------|
| CTO | ✅/⏭️ | [简要说明] |
| UX | ✅/⏭️ | [简要说明] |
| DEV | ✅/⏭️ | [简要说明] |
| QA | ✅/⏭️ | [简要说明] |

## 总览

| Task | 优先级 | PM | CTO | UX | DEV | QA |
|------|--------|----|-----|----|-----|----|
| 1. [需求标题] | [优先级] | ✅ | ⬜ | ⬜ | ⬜ | ⬜ |
| 2. [需求标题] | [优先级] | ✅ | ⬜ | ⬜ | ⬜ | ⬜ |

## Task 1: [需求标题]

- **需求来源**：overview.md > 需求 1
- **需求文件**：[name].md
- **设计文件**：design/[name]-cto.md, design/[name]-ux.md（待产出）
- **优先级**：[优先级]
- **PM**：✅
- **CTO**：⬜
- **UX**：⬜
- **DEV**：⬜
- **QA**：⬜

## Task 2: [需求标题]

...
```

## 规则

- PM 归档时必须填写"角色参与计划"表格，声明每个角色（CTO/UX/DEV/QA）的参与状态（✅参与 / ⏭️跳过）及简要理由
- 角色参与计划与 Task 详情列保持一致：计划中 ⏭️ 的角色，所有 Task 该列也应为 ⏭️
- 每条需求对应一个 Task，粒度为需求级别（粗粒度）
- PM 归档时 `PM` 列标记为 ✅，其余角色标记为 ⬜（或与角色参与计划一致）
- CTO 和 UX 字段支持三种值：✅（设计完成）、⏭️（跳过，无需设计）、⬜（待处理）
- DEV 和 QA 字段支持两种值：✅（完成）、⬜（待处理）；如需标记进行中可用 🔄
- 总览表和详情部分保持同步更新
- 历史归档中无"角色参与计划"章节时，CTO/UX/DEV 回退到检查各 Task 详情列（向后兼容）
- "需求文件"字段：PM 归档时填写，值为需求独立文件名（如 `fixbug.md`）
- "设计文件"字段：PM 归档时预填框架，CTO/UX 完成设计后更新为实际路径
  - UX 参与时：`design/[name]-cto.md, design/[name]-ux.md（待产出）`
  - UX 不参与时：`design/[name]-cto.md（待产出）`
  - 无设计需求时：`无`
- 历史归档（旧结构）中无"需求文件"和"设计文件"字段时，CTO/UX/DEV 按旧逻辑处理（向后兼容）
