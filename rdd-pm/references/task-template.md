# Task 模板

## 文件格式

```markdown
# Task Tracker

> 状态说明：✅ 完成 | ⬜ 待开始 | ⏭️ 跳过 | 🔄 进行中

## 角色参与计划

| 角色 | 参与状态 | 理由 |
|------|---------|------|
| CTO | 参与/跳过 | [简要说明] |
| UX | 参与/跳过 | [简要说明] |
| DEV | 参与/跳过 | [简要说明] |
| QA | 参与/跳过 | [简要说明] |

## 总览

| Task | 优先级 | PM | CTO | UX | DEV | QA |
|------|--------|----|-----|----|-----|----|
| 1. [需求标题] | [优先级] | ✅ | ⬜ | ⬜ | ⬜ | ⬜ |
| 2. [需求标题] | [优先级] | ✅ | ⬜ | ⬜ | ⬜ | ⬜ |

## Task 1: [需求标题]

- **需求来源**：pm/overview.md > 需求 1
- **PM 需求文件**：pm/[name].md
- **CTO 设计文件**：cto/[name].md（待产出）
- **UX 设计文件**：ux/[name].md（待产出）
- **优先级**：[优先级]
- **PM**：✅
- **CTO**：⬜
- **UX**：⬜
- **DEV**：⬜
- **QA**：⬜

## Task 2: [需求标题]

...
```

## 规则

- PM 归档时必须填写"角色参与计划"表格，声明每个角色（CTO/UX/DEV/QA）是否`参与`或`跳过`及简要理由
- 角色参与计划不使用 ✅/⬜/⏭️，避免和 Task 执行状态混淆
- 角色参与计划与 Task 详情列保持一致：计划中 `跳过` 的角色，所有 Task 该列应为 ⏭️；计划中 `参与` 的角色，所有 Task 该列初始为 ⬜（PM 除外）
- 每条需求对应一个 Task，粒度为需求级别（粗粒度）
- PM 归档时 `PM` 列标记为 ✅，其余角色标记为 ⬜（或与角色参与计划一致）
- CTO 和 UX 字段支持三种值：✅（设计完成）、⏭️（跳过，无需设计）、⬜（待处理）
- DEV 和 QA 字段支持两种值：✅（完成）、⬜（待处理）；如需标记进行中可用 🔄
- DEV 开始前，计划参与的 CTO/UX 必须为 ✅ 或 ⏭️；如果 UX 为 ⬜ 且 UX 设计文件不是 `无`，必须先提醒进入 `/RDD-UX` 或由用户明确跳过 UX
- 总览表和详情部分保持同步更新
- 历史归档中无"角色参与计划"章节时，CTO/UX/DEV 回退到检查各 Task 详情列（向后兼容）
- "PM 需求文件"字段：PM 归档时填写，值为 `pm/[name].md`
- "CTO 设计文件"字段：PM 归档时预填为 `cto/[name].md（待产出）`；CTO 完成设计后去掉"待产出"并更新状态
- "UX 设计文件"字段：UX 参与时预填为 `ux/[name].md（待产出）`；UX 不参与时填 `无`
- 无设计需求时，CTO/UX 对应字段填 `无`
- 历史归档（旧结构）中无"PM 需求文件"、"CTO 设计文件"、"UX 设计文件"字段时，CTO/UX/DEV 按旧逻辑处理（向后兼容）
