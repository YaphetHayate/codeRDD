# 模板集合

> 本文档是 [SKILL.md](../SKILL.md) 的补充材料，包含验证报告、完成汇报的呈现格式模板（提交规范已移交 QA，见 QA 的 `qa-workflow.md#第六步`）。

## 验证报告格式

```
验证报告：

┌──────────────────┬──────────┬─────────────────────┐
│ 检查项             │ 结果     │ 备注                 │
├──────────────────┼──────────┼─────────────────────┤
│ Lint              │ ✅ 通过  │                     │
│ TypeCheck         │ ✅ 通过  │                     │
│ 单元测试          │ ✅ 通过  │ 12/12 passed        │
│ 构建              │ ✅ 通过  │                     │
└──────────────────┴──────────┴─────────────────────┘
```

## 完成汇报格式

DEV 不再执行提交（移交 QA）。完成自测后向用户汇报并推进路由至 QA：

```
开发完成，自测通过：

┌──────────────────┬──────────┬─────────────────────┐
│ 检查项             │ 结果     │ 备注                 │
├──────────────────┼──────────┼─────────────────────┤
│ Lint              │ ✅ 通过  │                     │
│ TypeCheck         │ ✅ 通过  │                     │
│ 单元测试          │ ✅ 通过  │ 12/12 passed        │
│ 构建              │ ✅ 通过  │                     │
└──────────────────┴──────────┴─────────────────────┘

路由已推进至 QA，由 QA 执行功能验收 + 代码质量检查 + 提交门禁。
```

## 更新流转状态

开发完成的 task，路由推进一律经 CLI：`rdd-flow set-route -To QA -Phase VERIFY`（DEV 退场须带 `-QualityScanFile` 质量扫描凭据，见 `rdd-engine/references/task-routing.md`「统一交接门」）。路由单一真源在 task.json——**不改任何文档侧流转字段、不手写路由总览**；验证结果在交付说明中呈现（用户明确跳过 QA 时按下方「用户明确跳过 QA 时的处置」执行）。

## 分支纪律（DEV→QA 交接契约）

分支管理由 DEV 负责（创建分支、在其上工作）；`git commit` 由 QA 在提交门禁通过后执行（规范见 QA 的 `qa-workflow.md#第六步`）。QA 在 **DEV 已创建的分支**上提交、不创建/切换分支，因此：

- **命名**：优先遵循项目既有分支约定；无约定时用 `rdd/<归档名>/task-<n>`
- **留痕**：分支名写入交付说明，供 QA 对账
- **交接前置检查**：推进路由前确认工作分支仍处 checkout 状态、本次改动全部落在该分支上
- **并行限制**：单工作树同时只能 checkout 一个分支——多 DEV 会话并行且各建分支时，必须各自使用独立 `git worktree`/克隆；同一工作树下的并行会话不得各自建分支（在主干直接改动，或改为串行）

## 用户明确跳过 QA 时的处置

跳过 QA = 放弃验证模式的功能+质量双查与提交门禁，须用户显式裁决，DEV 不默认执行：

1. 与用户确认提交处置：用户自行提交 / 暂不提交（DEV 仍不执行 git commit）
2. 经 `delivery-bridge.cmd -Command decide -Kind checkpoint` 留痕（决策 = 跳过 QA + 提交处置方式，decider=user；用法见 SKILL.md「检查点留痕」）
3. 闭环方式按用户指令：用户明确要求闭环时，DEV 凭该裁决调用 `rdd-flow complete` 标记（此为跳过 QA 的例外路径；正常路径仍由 QA 标记），否则任务保持待 QA 状态
