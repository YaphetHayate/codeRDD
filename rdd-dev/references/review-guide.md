# 审查指南

> 本文档是 [SKILL.md](../SKILL.md) 的补充材料，包含分层审查策略与结果处理策略。

## 分层审查策略

子 agent 完成后，DEV 根据任务复杂度执行对应深度的审查：

| 任务复杂度 | 审查深度 |
|---|---|
| 简单（≤2 文件） | lint + 快速扫描关键逻辑 + 可运行性确认 |
| 标准（3-5 文件） | lint + 通读核心实现代码，检查是否符合设计意图 + 可运行性确认 |
| 复杂（5+ 文件或关键路径） | lint + 完整 code review：逐文件检查实现质量、边界处理、与设计文档的一致性、与其他模块的兼容性 + 可运行性确认 |

### 可运行性检查

无论任务复杂度如何，审查时都必须确认：

1. 子 agent 汇报的自测结果是否真实（lint/typecheck/测试是否确实通过）
2. 代码是否存在明显的编译/构建问题（如语法错误、缺失导入、类型不匹配）
3. 新增代码与项目已有代码的集成点是否正确衔接

## 结果处理策略

| 问题类型 | 处理方式 |
|---|---|
| 小偏差（风格、遗漏的边界处理） | DEV 直接修复，在汇报中说明 |
| 实现偏离设计 | DEV 评估影响，小偏离直接修，大偏离问用户 |
| 无法完成的任务 | 整理问题，问用户决策，按回答启动下一轮 |
| 文件范围越界 | 拒绝越界改动，重新执行该任务 |
