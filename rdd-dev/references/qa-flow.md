# QA 自动流转

> 本文档是 [SKILL.md](../SKILL.md) 的补充材料，描述开发完成后 QA 和 EVAL 的自动流转流程。

## 触发 QA

全部 task 开发完成并整体验证通过后，主动引导用户启动 QA：

> 所有开发任务已完成，验证通过。是否启动 QA 进行测试验证？（是 / 否）

**用户确认后：**

通过 Task 工具启动 QA 子 agent（subagent_type 为 `general`），prompt 包含：
1. 指令"加载 RDD-QA skill"
2. 归档路径（如 `.rdd/changes/archive/2026-06-04-engine-adapter-modularization/`）
3. 指令"基于 task.md 定位需求条目，执行 QA 流程"

QA 子 agent 完成后，DEV 收到结果并汇总呈现给用户。

**用户拒绝时：**

> 接下来你可以：
> - 输入 **/RDD-QA** 手动启动测试
> - 如果还有需要调整的地方，我们继续

## 触发 EVAL

QA 完成后（或用户跳过 QA 时）：

> 全部开发任务已完成。是否启动验收评价？（是 / 否）

**用户确认后：**

> 输入 **/RDD-EVAL** 进入验收评价模式，对本次需求的各角色产出和协同效率做回顾性审视。

**用户拒绝时：**

> 接下来你可以：
> - 输入 **/RDD-EVAL** 手动启动评价
> - 如果还有需要调整的地方，我们继续
