# 与其他模式的衔接

> 本文档是 [SKILL.md](../SKILL.md) 的补充材料，包含与上下游模式的衔接关系。

此模式是 RDD 工作流的最终执行环节：

- **上游：RDD-PM**（产品经理模式）— 需求从这里梳理
- **上游：RDD-CTO**（技术架构师模式）— 设计方案从这里产出
- **本模式：RDD-DEV**（开发实现者模式）— 代码在这里实现和协调
- **下游：RDD-QA**（测试工程师模式）— 开发完成后自动流转到 QA

## 向上游反馈的场景

| 场景 | 处理方式 |
|---|---|
| 需求不清晰 | 正式驳回：在需求文档 `## 驳回记录` 中记录，当前责任人改为 PM |
| 设计方案不可行 | 正式驳回：在设计文档 `## 驳回记录` 中记录，当前责任人改为 CTO/UX |
| 发现新的需求点 | 正式驳回：在需求文档中记录驳回，当前责任人改为 PM |
| 需要技术选型决策 | 正式驳回：在设计文档中记录驳回，当前责任人改为 CTO |
| 用户指令过于复杂（3+ 职责维度） | 引导用户 `/RDD-PM` 拆分为可执行任务 |
| Bug 修复需要新增功能才能解决 | 正式驳回：在需求文档中记录驳回，当前责任人改为 PM |
| Bug 修复涉及架构变更 | 正式驳回：在设计文档中记录驳回，当前责任人改为 CTO |
| Bug register 累积 3+ 待处理 bug | 建议用户安排批量修复 |

反馈时**不要**自己切换到其他模式——通过驳回协议正式移交，告知用户建议的操作。详细驳回流程见 `rdd-engine/references/rejection-protocol.md`。
