# 异常处理

> 本文档是 [SKILL.md](../SKILL.md) 的补充材料，包含四种异常场景的处理指南。

## 发现设计文档有误

在实现过程中发现 CTO 的设计文档与代码实际情况不符时：

1. **暂停该步骤的实现**
2. **记录具体差异**：文档说 X，实际代码是 Y
3. **评估影响**：这个差异是否影响整体方案可行性
4. **向用户报告**，给出建议：
   - 小偏差：直接调整实现，在代码注释中说明
   - 大偏差：建议回到 CTO 模式重新评估相关部分

## 发现需求有遗漏

实现过程中发现需求文档没有覆盖到的重要场景：

1. **继续实现已明确的部分**
2. **将遗漏点整理成清单**
3. **向用户报告**：

   > 实现过程中发现了几个需求文档没有覆盖的场景：
   > 1. [场景 A] — 我的处理方式：[...]
   > 2. [场景 B] — 需要你确认：[...]
   >
   > 如果场景比较多，建议输入 **/RDD-PM** 补充需求。

## 子 agent 产出质量不达标

审查子 agent 结果时发现质量问题：

1. **记录具体问题**：哪些文件、什么问题
2. **评估严重程度**：
   - 小问题（风格、遗漏）：DEV 直接修复
   - 大问题（实现偏离、逻辑错误）：整理问题清单，决定是重新启动子 agent 还是自己修复
3. **修复后重新验证**：确保修复没有引入新问题

## 实现卡住了

遇到技术难点，尝试了合理的方式仍然无法解决：

1. **判断卡住的原因**：
   - 如果是已有功能的 bug 导致卡住（非设计/需求问题）：
     - 阻塞当前任务 → 进入 **Bug 修复模式**（侧任务），按 Mode 4 的诊断→修复→验证流程处理
     - 不阻塞当前任务 → 记录到 `bug-register.md`，继续当前任务
   - 如果是设计/需求/其他原因 → 继续下面的步骤
2. **把已经尝试过的方式和结果整理清楚**
3. **向用户坦诚说明**
4. **建议**：
   - 如果是设计层面的问题 → `/RDD-CTO`
   - 如果是需求不清晰 → `/RDD-PM`
   - 如果是需要用户补充的技术信息 → 直接问用户
