# PM 两阶段收敛改造（已落地）

> 状态：**已实施**。落地范围 = 两阶段收敛改造 + 删除需求评估环节（用户裁决：PM 内评估从未有效，结构质量由独立审视员 AUDITOR 承接）。

## 设计

旧流程第三步把"对话 → 忠实记录"（保真）与"记录 → 拆解"（判断）压在同一次产出里一起确认，overview 实为拆解索引（事后产物），保真错误易被整洁的拆解件掩盖。

新流程拆成两道门：

- **门 1（保真门，第三步：收敛全貌）**：对话收敛后先产出完整不失真的「需求全貌（确认版）」，用户显式确认后才可拆解；
- **门 2（拆解门，第四步：基于 overview 拆解）**：以确认版全貌为唯一输入拆解，附"诉求 → 需求项"覆盖映射供用户抽查（轻量二道门）。

"不失真"的可执行定义（三原则）：**无遗漏**（每个确认点有落点，禁止跨主题合并丢失语义）、**无曲解**（语义差异处引原话锚点）、**无私自增删**（PM 推断须标注「PM 推断，待确认」）。

标准流程定型为五步：场景识别 → 场景对话 → **收敛全貌（硬门）** → **基于 overview 拆解** → 归档。需求评估环节整体删除。

## 已知取舍

- **单需求标准归档无 AUDITOR 审视**：AUDITOR 触发判据为 ≥2 条子需求（单需求快速通道豁免），删除 PM 评估后，"值不值得做"（必要性/价值）的判断不再有流程内把关——按用户裁决接受：经验上 PM 内评估从未有效，且最终决定权本就在用户。
